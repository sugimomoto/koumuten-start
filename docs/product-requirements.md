## 機能要件

### R-01 施工事例（いちばん見せたいコンテンツ）
- 内容：施工した家を1件ずつ載せる。載せる情報は、写真・場所・工期・築年数・費用（概算）・お客様の声。場所は細かい住所を出さず、区・市までの粗さにする。
- 受け入れ条件（利用者がやること・見えること）：
  - [ ] 来訪者が施工事例の一覧を開くと、施工事例が写真つきで並んで見える
  - [ ] 来訪者が施工事例を1件開くと、その事例の写真が見える
  - [ ] 来訪者が施工事例を1件開くと、場所・工期・築年数が見える
  - [ ] 事務担当が管理画面で施工事例を追加して公開すると、来訪者が見る一覧にその事例が出る
- 根拠：[00:49] [01:05] [01:10] [01:20] [01:26]
- テスト：`tests/e2e/works.spec.ts`（一覧／詳細／1件選ぶ）・`tests/e2e/works-admin.spec.ts`（管理画面から追加して公開）

### R-02 施工事例の費用（概算）
- 内容：費用は「約○○万円」の概算で載せる。出したくない事例は空欄にでき、空欄のときは費用を表示しない。
- 受け入れ条件：
  - [ ] 来訪者が、費用を入力した施工事例を開くと、「約○○万円」の形で概算の費用が見える
  - [ ] 来訪者が、費用が空欄の施工事例を開くと、費用はどこにも表示されない
- 根拠：[01:29] [01:32] [01:40] [01:49] [01:57]
- 備考：当初は「金額を出すと高いと思われて終わる」として出さない案だったが、問い合わせの電話で最初に聞かれるのが費用であることから、概算を出すことに変更された。
- テスト：`tests/e2e/works.spec.ts`「費用を入力した施工事例…約○○万円が見える」「費用が空欄…表示されない」

### R-03 施工事例の種類での絞り込み
- 内容：施工事例を「リフォーム」「新築」「修繕」の種類で分けて見られるようにする。
- 受け入れ条件：
  - [ ] 来訪者が施工事例の一覧で「リフォーム」を選ぶと、リフォームの事例だけが並び、ほかの種類の事例は出ない
  - [ ] 来訪者が「新築」を選ぶと、新築の事例だけが並ぶ
  - [ ] 来訪者が「修繕」を選ぶと、修繕の事例だけが並ぶ
  - [ ] 来訪者が絞り込みを解除すると、すべての種類の事例が並ぶ
- 根拠：[02:01] [02:09]
- テスト：`tests/e2e/works.spec.ts`（リフォーム／新築／修繕／解除／いまどの種類か）

### R-04 お客様の声（施工事例の中に出す）
- 内容：お客様の声は独立したページにせず、その家の施工事例の写真の下に出す。施工事例ごとに入力できる欄を用意し、掲載の許可が取れたものだけ入力する運用にする。
- 受け入れ条件：
  - [ ] 来訪者が、お客様の声を入力した施工事例を開くと、写真より下に「お客様の声」として声の内容が見える
  - [ ] 来訪者が、お客様の声が空欄の施工事例を開くと、「お客様の声」の見出しも内容も表示されない
  - [ ] 事務担当が管理画面で施工事例を編集すると、その事例のお客様の声を入力する欄がある
- 根拠：[02:14] [02:25] [02:29] [02:35] [02:52] [03:00]
- 備考：掲載許可の取り方（はがきのチェック欄）は未決事項 U-03。ただし「入力欄を用意し、許可が取れたものだけ入力する」という作りは決定済みなので、入力欄の実装は進めてよい。

### R-10 問い合わせフォーム
- 内容：フォームから問い合わせを受け取る。ご相談の種類（リフォーム・新築など）を選ぶ欄を作る。送信されたらメールで知らせる。迷惑メール対策を入れる。
- 受け入れ条件：
  - [ ] 来訪者が問い合わせフォームを開くと、ご相談の種類を選ぶ欄があり、リフォーム・新築などから選べる
  - [ ] 来訪者が必要な項目を入れて送信すると、受け付けたことがわかる表示が出る
  - [ ] 来訪者が必要な項目を空のまま送信すると、送信されず、どこを直せばよいかがわかる表示が出る
  - [ ] 問い合わせが送信されると、山田工務店にメールで知らせが届く
  - [ ] 迷惑メール（スパム）対策により、自動送信とみなされる送信は受け付けられない
- 根拠：[03:24] [03:28] [03:36] [03:46] [03:51] [03:57]
- テスト：`tests/e2e/contact.spec.ts`（種類を選ぶ欄／受付の表示／エラーの表示／入力の保持／メール通知／自動送信は受け付けない）
